# Security cleanup

This repository is public. Until the `10-31-26-updates` branch, it carried the Android release
signing key (`android/app/soothe-quest-release.keystore`), its passwords written into
`android/app/build.gradle`, and `android/local.properties`.

They are removed from the current tree, and `.gitignore` now keeps them out. **They are still in
the git history and anyone may already have copied them**, so treat the key as exposed.

## Before you pull this change

Pulling a commit that deletes a tracked file deletes it from your disk. **Copy
`android/app/soothe-quest-release.keystore` somewhere safe outside the repo first.**
(`android/local.properties` is regenerated by Android Studio, so losing it does not matter.)

## Signing release builds now

Follow "Release signing (Android)" in `README.md`: put the keystore in `android/app/` and copy
`keystore.properties.example` to `keystore.properties` at the repo root. Both are git-ignored.

CI can set `SQ_KEYSTORE_FILE`, `SQ_KEYSTORE_PASSWORD`, `SQ_KEY_ALIAS` and `SQ_KEY_PASSWORD`
instead. Without either, release builds come out unsigned rather than failing.

## What still has to be done

1. **Replace the upload key.** The key and its password are public, so anyone can sign an APK as
   this app. If the app uses Play App Signing, request an upload key reset in Play Console
   (Setup → App signing), generate a new keystore with a new password, and use it from then on.
2. **Purge the history.** Removing the files from the latest commit does not remove them from
   GitHub. Rewriting history (for example `git filter-repo --invert-paths --path
   android/app/soothe-quest-release.keystore --path android/local.properties`, plus replacing
   the password text) needs a force-push to every branch, and every existing clone must be
   re-cloned afterwards. Do this only after step 1.
